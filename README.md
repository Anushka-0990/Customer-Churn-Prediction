# Customer Churn Prediction & Business Recommendation Engine

Predicts which telecom customers are likely to churn and translates the model's
 **use data to drive a business
decision.**

---

## 1. Business Problem

Telecom companies lose 15–30% of their customer base to churn every year, and
acquiring a new customer costs 5–7x more than retaining an existing one. This
project identifies **which customers are at risk of leaving and why**, so a
retention team can act *before* they churn rather than after.

## 2. Dataset

[IBM Telco Customer Churn dataset](https://raw.githubusercontent.com/IBM/telco-customer-churn-on-icp4d/master/data/Telco-Customer-Churn.csv) —
7,043 customers, 21 features covering demographics, account information,
services subscribed, and billing details. Overall churn rate: **26.5%**.

## 3. Approach

1. **Data cleaning** — handled missing `TotalCharges` values, encoded the target.
2. **Feature engineering** — added tenure buckets, average monthly spend, and
   an add-on service engagement count (business-relevant, not just raw columns).
3. **EDA** — investigated churn by contract type, tenure, monthly charges, and
   service engagement to surface business patterns before modeling.
4. **Modeling** — trained and compared Logistic Regression (interpretable
   baseline) vs. Random Forest (captures non-linear patterns), selected by
   ROC-AUC since churn is an imbalanced classification problem.
5. **Business translation** — converted feature importances and EDA findings
   into specific retention recommendations with estimated impact.
6. **Deployment** — packaged as an interactive Streamlit app for real-time,
   single-customer risk scoring.

## 4. Key Findings

| Driver | Finding |
|---|---|
| **Contract type** | Month-to-month customers churn at **42.7%** vs. ~2.8% for two-year contracts |
| **Tenure** | Customers in their first year churn at **47.4%** — the highest-risk segment |
| **Service engagement** | Customers with 0 add-on services churn at **21.4%**; those with more add-ons churn far less |
| **Top predictive features** | Tenure, Total Charges, Contract type, Internet Service type, Average Monthly Spend |

## 5. Model Performance

| Model | Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---|---|---|---|---|
| Logistic Regression | 0.736 | 0.502 | 0.791 | 0.614 | 0.843 |
| **Random Forest (selected)** | **0.760** | **0.534** | **0.765** | **0.629** | **0.844** |

Random Forest was selected as the production model based on ROC-AUC. Recall is
prioritized over precision for this use case — in retention, the cost of
missing a customer who *would* churn is higher than the cost of a wasted
retention offer to someone who wouldn't have.

## 6. Business Recommendations

Full detail in [`outputs/business_recommendations.txt`](outputs/business_recommendations.txt).
Summary:

1. **Incentivize contract upgrades** — offer a loyalty discount to migrate
   month-to-month customers to 1-year contracts.
2. **Build a first-year retention journey** — proactive check-ins and
   early-tenure offers for the highest-risk segment.
3. **Bundle add-on services** — free trials of Online Security / Tech Support
   for low-engagement customers to increase stickiness.
4. **Operationalize the model** — feed churn-risk scores into a CRM "at-risk"
   flag to trigger targeted retention campaigns.
5. **Estimated impact** — a 10% reduction in churn among flagged high-risk
   customers would retain ~186 additional customers from this dataset alone.

## 8. How to Run Locally

```bash
# 1. Clone the repo
git clone https://github.com/<Anushka-0990>/customer-churn-prediction.git
cd customer-churn-prediction

# 2. Install dependencies
pip install -r requirements.txt

# 3. Run the EDA (optional — outputs already included)
python src/eda.py

# 4. Train the model (generates models/churn_model.pkl + outputs/)
python src/train_model.py

# 5. Launch the interactive app
streamlit run app/app.py
```

## 9. Deployment
1. Push this repo to GitHub.
2. Go to share.streamlit.io → "New app" → select this repo → set the main
   file path to `app/app.py`.
3. Deploy. The trained model must be committed to the repo (it already is, in
   `models/churn_model.pkl`) since Streamlit Cloud doesn't run `train_model.py`
   automatically.
